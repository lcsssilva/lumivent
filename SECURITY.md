# Security policy

## Supported versions

Security fixes are applied to the latest stable version.

| Version | Supported |
|---|---|
| 1.x | Yes |
| < 1.0 | No |

## Reporting a vulnerability

**Do not open a public issue for vulnerabilities.**

Use GitHub's private channel:

1. Go to <https://github.com/lcsssilva/lumivent/security/advisories/new>.
2. Describe the problem, the affected version and your hardware/system.
3. Include reproduction steps, the impact and, if possible, a proof of concept.
4. If there is no fix yet, agree on a disclosure date with the maintainer
   (usually 90 days).

You will get an acknowledgement within 7 days. Critical issues are handled
first; the fix and the advisory are published in a release with a security
note.

## Scope

Lumivent runs as a regular user, but it talks to sensitive devices. In scope:

- udev rules and permissions (`uaccess`) that expose devices beyond what is
  needed;
- the `lumivent-nvme-smart` helper and its use of `cap_sys_admin` /
  `cap_dac_read_search`;
- reads and writes through `dart:ffi` on hidraw, I²C/SMBus and sysfs;
- driver commands that could damage hardware or bypass safety checks
  (motherboard, GPU and SMBus);
- effect import (HTML, folder, ZIP and Windows cache), including path
  traversal, ZIP bombs and JavaScript execution in the QuickJS runtime;
- configuration import and writes to `config.json`;
- the `systemd --user` unit generated by the app.

Out of scope:

- vulnerabilities in third-party dependencies already fixed upstream (report
  them to the original project; let us know if Lumivent needs an update);
- issues that require prior root access or local changes to the udev rules;
- social engineering, phishing or physical attacks.

## Good practices for users

- Only install packages from the official releases, or build from source.
- Verify the `sha256sums.txt` checksum before installing a `.pkg.tar.zst`.
- Do not add your user to the `i2c` group; the `uaccess` rules already cover the
  app's devices.
- Only import effects from sources you trust: an effect runs JavaScript inside
  the app's runtime.
- Keep the package up to date with `pacman -Syu`.

## Responsible disclosure

We ask that you:

- allow reasonable time for a fix before disclosing publicly;
- avoid accessing third-party data, disrupting services or destroying hardware;
- act in good faith, without extortion or financial demands.

We will not take legal action against researchers who follow this policy.
